UZ Core Flag фиксирует решение о допуске к донации для [пациента UZ Core](StructureDefinition-uz-core-patient.html). Отметка может ссылаться на [посещение](StructureDefinition-uz-core-encounter.html) и автора. Активная отметка может означать как допуск, так и медицинский отвод: статус описывает жизненный цикл отметки.

### Обязательные и Must Support элементы

[Must Support](must-support.html)

#### Каждый UZ Core Flag должен содержать

Статус, код решения о допуске и ссылку на пациента. Эти элементы обязательны в базовом FHIR R5.

#### Каждый UZ Core Flag должен поддерживать

- бизнес-идентификатор вместе с его системой, если он присвоен;
- статус отметки;
- решение о допуске к донации;
- пациента, к которому относится решение.

### Пошаговое создание JSON

1. Начните с [минимального JSON](Flag-example-donation-minimal-flag.json.html): профиль, язык, статус, решение и ссылка на пациента.
2. В [JSON допуска](Flag-example-donation-eligible-flag.json.html) добавлены административная категория, посещение, автор и период действия.
3. [JSON медицинского отвода](Flag-example-donation-deferred-flag.json.html) содержит клиническую отметку. Пока отвод действует, её статус также active.

JSON генерируется из FSH-примеров. Для кода решения используйте указанную систему кодирования; категории HL7 сохраняют исходную систему. Ссылка subject указывает на UZ Core Patient. См. [Быстрый старт](#quick-start).
